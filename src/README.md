# Gym Management System — JDBC Module

This version keeps the existing Java Swing application and connects its CRUD operations to the existing MySQL database `gym_management`.

## Module 5 concepts used

- `DriverManager` and `Connection` for database connectivity
- `PreparedStatement` with parameters such as `setInt`, `setString`, `setDouble`, `setDate`, and `setTime`
- `ResultSet` and `rs.next()` to read query results
- `executeQuery()` for `SELECT`
- `executeUpdate()` for `INSERT`, `UPDATE`, and `DELETE`
- `SQLException` handling
- try-with-resources to close JDBC resources safely

## CRUD features

- **Members:** add regular/premium members, display, update, and delete
- **Trainers:** add, display, update, and delete
- **Membership plans:** add, display, update, and delete
- **Fitness schedules:** add, display, update the activity/date/time, and delete
- The existing “Process Next” button still demonstrates the original in-memory queue; processing a queue item does not delete its database row.

## Existing database

The project uses the existing database and table names. It does not drop or clear data. On startup, `DatabaseSetup` uses `CREATE TABLE IF NOT EXISTS` to ensure the four tables exist. Existing tables are not altered by those statements.

The expected table columns are:

- `members`: `member_id`, `name`, `age`, `phone`
- `trainers`: `trainer_id`, `name`, `specialization`, `phone`
- `membership_plans`: `plan_id`, `plan_name`, `duration`, `price`
- `fitness_schedules`: `schedule_id`, `schedule_date`, `schedule_time`, `member_name`, `trainer_name`, `activity`

Member, trainer, and plan IDs are entered manually because their existing columns are not auto-increment. Schedule IDs are generated by MySQL.

**Existing-schema limitation:** the `members` table does not contain a membership-type column. The GUI can distinguish a newly added Premium member during the current run, but after restarting the application records loaded from MySQL are treated as Regular members. The schema is deliberately not changed for this implementation.

## Configure the connection

Open `src/database/DatabaseConnection.java` and confirm the JDBC URL, MySQL username, and password match your local MySQL setup. Keep credentials private.

The URL should normally be:

```text
jdbc:mysql://localhost:3306/gym_management
```

Make sure MySQL Server is running and the Connector/J JAR is in `lib/`.

## Run from VS Code terminal (PowerShell)

From the `GymManagementSystem` project folder, run:

```powershell
$files = Get-ChildItem -Path .\src -Recurse -Filter *.java | ForEach-Object { $_.FullName }
New-Item -ItemType Directory -Force -Path .\build\classes | Out-Null
javac -cp ".\lib\mysql-connector-j-26.7.0.jar" -d .\build\classes $files
java -cp ".\build\classes;.\lib\mysql-connector-j-26.7.0.jar" Main
```

If your Connector/J JAR has a different filename, replace the filename in both commands with the one inside your `lib` folder.

## Suggested test order

1. Run `database.TestConnection` if you want to check the connection first.
2. Start `Main`.
3. Add a member, then display, update, and delete a member.
4. Add a trainer, then display, update, and delete a trainer.
5. Add a membership plan, then display, update, and delete it.
6. Add a schedule, then display, update, and delete it.
7. Restart the application and verify that records not deleted from MySQL remain saved.
